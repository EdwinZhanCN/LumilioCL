## 编号与开发步骤

- `H-*`：HMCL 的用户流程家族。编号不随按钮名称、路由或文件位置变化。
- `L-*`：LumilioCL 的目标业务流程；可对应多个 H 流程，也可以没有 HMCL 对应项。
- `AC-*`：状态与恢复文档中的验收场景，描述可观察结果，尚未执行的场景不能写成通过。
- `FLOW-REF-*`：architecture 中的精确参考文件映射；不是可直接搬用的模块设计。

开发一个功能时：

1. 在 HMCL 对照中定位 H 编号，确认 LumilioCL 范围和对应 L 契约。
2. 阅读该 L 流程与相关 behavior 文档，核对真实实现差距；创建执行计划。
3. 按状态与恢复文档明确前置条件、操作输入、提交边界、终态和重启行为。
4. 若需新增参考文件，先在 architecture 登记精确文件，再读源码并用自己的语言补充行为。
5. 实现领域服务，再接入现有 ARCH 页面；为适用 AC 场景选择 core/UI/app 验证边界。
6. 记录实际证据，更新当前行为与差距；按 AGENTS 的四步验证闭环完成。

完整流程必须说明：入口、对象与前置条件、主线、选择和分支、成功去向、取消/失败去向、持久事实、重启行为、验收场景。副作用操作始终绑定发起时选定的实例及输入，不能随用户切换当前路由改变目标。

## 当前范围与未决事项

| 能力 | 归属或约束 |
|---|---|
| 收藏、集合、会话历史、实例快照 | LumilioCL 自有流程，分别映射 Library / Home / Instance.History；无需伪造 HMCL 对应能力 |
| 全局账户、全局默认、Java 管理、应用维护 | core/App State 有相关职责，但 ARCH 尚未明确完整的全局 UI 入口；记录在 proposed [ADR 0008](../../.agents/decisions/0008-workflow-coverage-boundaries.md) |
| 在线认证和秘密存储 | App State 给出未来凭据边界；客户端注册、协议、UI 流程仍需独立决策与计划 |
| 任意外部实例根、目录登记/切换 | HMCL 有流程；App State 首轮明确不支持自定义实例数据根，不照搬 |
| 联机、通用 NBT/原理图编辑、主题包、外部种子工具 | 参考盘点保留，当前不扩展 ARCH；若纳入先做范围 ADR |
| 启动器自动更新、完整备份恢复、共享资源回收 | 有参考行为或目标需求，不代表已有产品入口和服务能力 |

## 维护边界

参考升级时，重新核对基线、入口链及条件；只更新受影响的 H 流程和证据，保留编号。HMCL 函数存在不证明入口可达；UI 声明也不证明平台/凭据服务能运行。新增条件或失败分支应同步更新 L 契约和 AC 场景。

业务规则尽量只在所属文档定义一次：目录树在 App State，当前细节在 behavior，用户流程在本目录。状态表是设计词汇，不要求实现一个包揽所有页面与领域的全局枚举。
