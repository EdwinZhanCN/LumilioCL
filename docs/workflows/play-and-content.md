# 游玩、身份、内容与世界

[返回入口](README.md) · [HMCL 对照](hmcl-reference.md) · [实例生命周期](instance-lifecycle.md) · [状态与恢复](state-and-recovery.md)

以下是 LumilioCL 目标流程及已核对的当前差距。业务 I/O 与规则留在 core，UI 负责输入、展示和导航；本文件不定义新增页面、产品文案或在线认证协议。

## L-ACC-01 — 离线身份管理与选择

参考：H-ACC-02/06/08、H-PLAY-02。账户独立于实例；全局 UI 入口仍待 ADR 0008 解决，不把它假装成某个实例的私有身份。

主线：显示账户或无账户 → 新建并验证名称 → 保存公开 profile → 选择账户 → 之后发起的 launch 捕获该身份。当前名称忽略大小写去重，首个新增账户自动选中；删除当前账户选剩余首个或无账户，见 [settings](../behavior/settings.md)。

取消输入不保存；保存失败不报告已添加。删除账户只影响身份选择，不删除世界、实例或按该 UUID 保存的游戏数据。切换身份不修改已运行会话。

已解决（计划 0027）：未选择账户时 service.launch 返回 NoAccount，不再回退为 Player，与 diagnostics 一致；UI 在启动时先弹出添加账户弹窗，添加后继续，取消则不启动。当前游戏同样保存在 settings.json。

离线 profile 的 UUID 规则沿用 [launcher-spine](../behavior/launcher-spine.md)；手工 UUID 现已支持（只在添加时设置，格式校验，不与现有账户重复）；restricted 与皮肤能力不自动加入。验收：AC-ACCOUNT-01、AC-RACE-01。

## L-ACC-02 — 在线登录与认证恢复（Microsoft 已实现，见 ADR 0013；第三方认证待做）

参考：H-ACC-01/03/04/05/07/11/12、H-PLAY-04。目前无完整在线认证服务。实施前需决定客户端注册、支持的协议/账户、角色选择及离线资格。

目标主线：用户选择认证方法 → 获取授权信息 → 外部授权/输入 → 等待回调或轮询 → 验证资格与角色 → 保存公开信息和系统凭据引用 → 发布可选择身份。等待必须可取消且有过期结果；过期后创建新授权尝试，不继续使用旧设备码。

失败分支：凭据过期请求重新登录；服务不可达允许重试/返回；只有符合已定义资格的账户可使用已有离线身份。不能把认证异常全部转成离线账户，也不能把未拥有游戏的身份显示为可在线启动。

秘密按 App State 放系统库；库不可用时提供本次会话登录，不落明文 JSON。退出登录与移除公开登记、撤销远端授权是不同动作，实施计划要分别定义。皮肤与认证服务器管理并非首轮默认能力。

重启只恢复公开信息、凭据引用和验证后的身份；不恢复授权码、轮询句柄或“正在登录”证明。验收：AC-AUTH-01、AC-SECRET-01。

## L-RUN-01 — 发现、选择和管理 Java

参考：H-SET-01..05、H-PLAY-03。实例 Settings.Java 配置运行时；全局运行时管理入口待定。

主线：后台发现常规目录、用户登记目录与托管 runtimes → 按真实路径去重 → 检测版本/架构 → 根据实例需求和显式设置选择 → 启动前验证。显式选择优先并不等于可以绕过不兼容校验。

当前选择顺序见 [launcher-spine](../behavior/launcher-spine.md)：明确选择；否则所需 major 的精确匹配或最小更新版本；未声明需求时优先 Java 8，否则最小版本。更宽泛的“推荐运行时”策略需另定，不能根据 HMCL UI 文案猜测。

目标管理分支：无兼容运行时 → 展示原因 → 用户选择本机 Java、安装适合当前平台的托管 Java或取消。下载归档需要校验、临时解压和发布；安装成功后重新探测。外部 Java 只移除登记/禁用，不删除用户系统安装。卸载托管 Java前核对运行会话和操作引用，不暗中清掉依赖。

Java 与 natives 按 platform-key 隔离是 App State 的 P2 目标；当前路径未全部迁移。清 cache 不能删除已装 Java。当前 core 有探测/选择能力，不证明在线运行时安装及卸载流程已实现。验收：AC-JAVA-01、AC-JAVA-02、AC-OFFLINE-01。

## L-SET-01 — 默认设置、实例覆盖与高级设置

参考：H-SET-06..10。实例 Settings 的 Game/Runtime/Java/Performance/Advanced 是既有节点；全局默认的 UI 入口待决策。

主线：加载全局默认和实例覆盖 → 展示实际生效值及其来源 → 修改并校验 → 原子保存 → 后续操作捕获新配置。恢复继承应移除覆盖，不把当前默认复制成永久覆盖。

失败：非法内存范围、未知运行时或不安全输入拒绝且保留旧设置；保存失败不能展示“已保存”。部分高级项必须按 OS/架构/游戏版本筛选。运行中的进程沿用启动时参数，变更默认不重配该进程。

首轮不继承 HMCL 的任意工作目录/版本隔离切换：实例可变目录已固定隔离。若引入预设、前后置命令、包装器、渲染后端等，分别按 ARCH 归属实施并定义副作用，不用“Advanced”掩盖范围扩展。未知 schema 保留原件并拒绝写入；HMCL 的备份覆盖提示不构成静默强制覆盖授权。

真实模式已接入全局设置页与游戏页·设置各分组（计划 0028、0029）。当前 settings 写入失败保留已保存投影；实例覆盖保存前和启动前校验生效内存组合。全局 settings 和实例 overrides 的字段范围不同于完整 HMCL 设置列表，见 [settings](../behavior/settings.md)。验收：AC-SETTINGS-01、AC-PERSIST-01、AC-RACE-01。

## L-PLAY-01 — 启动、运行、停止与会话结束

参考：H-PLAY-01/02/03/05/06/09/10。入口：Home Continue/Recent、Library 行、Instance Overview；测试启动从 Diagnostics 发起仍调用同一领域服务。

1. 捕获实例、身份、生效设置及本次会话标识；核对实例仍存在及冲突操作。
2. 解析启动配置和环境 → 检查已装依赖 → 必要时下载/修复 → 校验 → 选择 Java。
3. 在线身份按认证契约刷新，离线身份无需联网认证；当前只实现离线身份。
4. 构造参数 → 创建进程 → 等待可观察的就绪判定。取得 PID 不是 running。
5. 发布 running，用户可观察日志或请求停止；继续监督进程直至结束。
6. 正常退出、崩溃、启动早退和用户停止分别记录会话结果；更新 History/Recent/Needs Attention。

取消准备任务与停止运行进程是不同命令。导航离开 Home 只换页面，不取消任务；再次启动需要显式处理重复请求，不能生成两个竞争写同一 game 目录的进程。实际进程停止确认前不显示已停止。

当前：LaunchSession 是进度 reducer；running 后还接受 exited，不能当永久终态。当前 reducer 在 running 后忽略 cancelled，停止需通过进程监督并最终提供退出事实，不能只对 reducer 塞 Cancelled。process 的启动标记/settle time 规则见 [launcher-spine](../behavior/launcher-spine.md)。不把启动成功动画当就绪判断。

当前 service.launch 等待 launch 返回后记录会话并 mark_installed；前期错误通过 `?` 返回可能未形成会话历史。目标需覆盖这些失败与安装事实提交时机。installed 完整依赖支持离线启动；cache 失效不能强迫已装实例先取最新目录。

当前（计划 0017）：前期失败/取消、崩溃、早退、用户停止各记入 history，`install_instance` 独立于启动；运行中的启动有会话标记，启动器异常退出后下次启动记为 interrupted 并报告，不重新监督。

重启：进程句柄、取消令牌、认证响应和启动百分比失效。重新探测并核对进程/会话身份；仅 PID 相同不足以继续监督。不自动再启动上次游戏。验收：AC-LAUNCH-01..04、AC-OFFLINE-01、AC-OPS-02。

## L-PLAY-02 — 快速进入游戏目标（待实现）

参考：H-PLAY-07、H-WORLD-01。目标为世界、服务器或 Realm，是否纳入各类支持需在计划确定。

主线：选择目标 → 检查对应游戏版本能力 → 形成此次 launch 的显式参数 → 复用 L-PLAY-01 → 游戏按目标进入。不可用时告知原因并让用户选择普通启动，不悄悄改进另一世界。

目标不是联机隧道，不替代服务器可达性、账户资格或 Minecraft 内连接错误处理。世界目录或地址不得作为任意命令片段拼接。当前没有完整 Quick Play 业务流程的交付证据。验收：AC-QUICK-01。

## L-DISC-01 — 搜索、项目详情与安装意图

参考：H-DISC-01..05、H-TASK-04。入口：Discover 的四类内容；HMCL 世界下载不扩大当前 Discover。

主线：类型、查询、兼容条件、分类、排序、分页 → 发起读取 → 展示结果/空结果/失败 → 查看项目 → 选择发布 → 选择/确认目标实例 → 形成安装意图 → 转 L-CONT-01 或 L-LIB-03。

返回详情前的列表保留本次窗口的查询、页码和滚动；切换类型按现有 [discover](../behavior/discover.md) 重置不适用条件。所有列表/详情/图片响应要与当前请求版本匹配，过时响应不能覆盖新结果。错误不能丢掉用户查询后显示“没有结果”。

同一发布在不同目标实例的兼容性不同。UI 禁用不兼容选项，core 再拒绝不兼容输入；服务不把显式旧发布偷换为最新发布。required/optional/incompatible 依赖如何安装属于待定策略，当前展示元数据不等于已实现依赖解析器。

详情返回、外部链接、复制链接是 UI/系统操作，不属于持久业务任务。HTTP/图片可缓存但不是已装内容的事实。另存为下载是待定扩展，与安装到实例区分。验收：AC-DISC-01、AC-CONTENT-01、AC-RACE-01。

## L-CONT-01 — 获取并安装内容

参考：H-DISC-04、H-CONTENT-02/09/11。入口：Discover 或 Instance.Content 对应类别。

主线：冻结目标实例、项目、发布、选定文件和目标种类 → 检查兼容及文件名 → 注册 Activity → 下载/校验临时文件 → 提交到该实例 mods/resourcepacks/shaderpacks → 扫描 → 写 Changes 与操作结果。

没有兼容版本就返回明确结果，不写文件。默认选版本/primary file 的具体策略沿用 discover；用户显式选版本时尊重选择。大小/hash 验证失败或取消保留已有目标文件。提交已完成后失败于日志记录，应报告文件已变更而记录失败，不能假装什么都没发生。

本地导入复用路径、冲突及扫描规则；批量逐项返回结果。对同名文件不能默认覆盖用户本地修改，替换需要定义权限与预期旧文件。界面切换实例或删除来源项目不重定向已发起的任务。

当前（计划 0018）：online service 会形成任务与 history；同名异内容文件不被静默覆盖（冲突）；启停/删除经 service 持实例租约并逐项返回。本地添加已接入（计划 0026）。验收：AC-CONTENT-01、AC-CONTENT-02、AC-RACE-01、AC-OPS-01。

## L-CONT-02 — 扫描、可用性切换与删除

参考：H-CONTENT-01/03/04/05/09/10。入口：Instance.Content，实际文件为权威来源。

主线：后台扫描 → 显示元数据/未知元数据 → 搜索与选择 → 启用、禁用、删除或定位 → 重新扫描 → 记录确实发生的变更。扫描中、目录空、扫描错误应分开；损坏元数据不应悄悄隐藏用户文件。

文件操作只接受经过验证的本地文件名/相对位置，不接受任意绝对路径；不跟随链接到实例外。同状态的切换无副作用；目标名称冲突不覆盖。多选操作返回逐项结果，不能用一次“成功”遮掉失败。

当前 content 的 `.disabled` 语义是文件可用性；资源包/光影的游戏选择还受 options.txt、加载器和模组配置影响。资源包“游戏内已选中”、光影“已应用”必须另有事实与策略，不能从文件存在/改后缀推断。

游戏运行时的启停/删除已由 service 实例租约拒绝（0018）；更细粒度一致性仍未证明。当前字段、扫描、文件边界见 [content](../behavior/content.md)。验收：AC-CONTENT-02、AC-RACE-02、AC-FILES-01。

## L-CONT-03 — 检查、应用与回退更新

参考：H-CONTENT-06/07/08；更新入口属于 Instance.Content，执行归属 Activity.Updates。

主线：捕获实例与待查文件/hash → 查识别及兼容候选 → 区分未知、最新、可更新、检查失败 → 用户选择 → 下载新文件 → 校验 → 提交 → 按预期旧文件删除或替换 → 重扫并写历史。

检查与执行之间必须核对旧文件身份；文件被游戏/用户修改则报告冲突，不删除新出现的同名文件。批量允许部分成功，每个项有结果。整合包内容独立更新需要提示其管理关系，不承诺下次包更新会保留所有修改。

当前 updates 只检查 enabled 文件，跳过 folder packs 和不可读项；规则见 [updates](../behavior/updates.md)。不支持项与未知项不能合并成“已是最新”。下载失败保留旧文件已有保证，但跨多文件事务、预期旧身份守卫和重启恢复需独立验证。

回退只有保留且校验了旧文件/manifest 才可提供；当前没有完整版本保留与回退服务，不能从 HMCL 按钮推导本项目能力。验收：AC-UPDATE-01、AC-RACE-01、AC-OPS-02。

## L-WORLD-01 — 浏览世界与状态

参考：H-WORLD-01/04。入口：Instance.Worlds。

主线：扫描 saves → 解析有界世界元数据 → 展示名称、版本、时间、损坏/锁状态 → 选择世界查看或操作。缺 saves 是空库；解析损坏仍保留可操作条目，不由数据库覆盖游戏写入的名称与时间。

不能把“最后游玩世界”当“当前运行世界”；实例运行、世界锁和历史是不同证据。文件打开/世界详情刷新失败展示问题，不删除世界。当前只读解析与排序规则见 [worlds](../behavior/worlds.md)，世界锁的完整产品守卫尚待实现。验收：AC-WORLD-01、AC-FILES-01。

## L-WORLD-02 — 复制、删除、导入、导出与编辑

参考：H-WORLD-02/05..09/11/12。复制/删除属于现有 Worlds；导入、导出、属性编辑、数据包管理仍须计划定义具体能力。

主线：明确选中世界及操作范围 → 检查游戏/世界锁和目标名称 → 用户确认 → 用临时目标完成必要文件工作 → 发布 → 重扫 → 记录 Changes。只读操作不阻塞为写操作；写操作不能使用过期世界对象。

复制不覆盖目标，失败移除本次残留；删除不能删除整个 saves 或实例。游戏运行时的世界写入默认阻止，直到证明更细粒度一致性。世界归档与整合包格式不同；导入需检查安全路径、容量和内容，不能按扩展名信任。

若增加属性/NBT 编辑，需保留未知字段，明确可编辑字段和版本条件，并避免覆盖游戏刚写入的文件；通用 NBT 编辑器仍在范围外。数据包是世界文件，不等同实例 mods。当前 core 具备世界扫描、复制、删除（计划 0019：service 租约、链接守卫、暂存发布），不具备全部 HMCL 编辑能力。验收：AC-WORLD-02、AC-RACE-02、AC-FILES-01。

## L-HIST-01 — 变化、会话与快照

参考：H-WORLD-10；Changes/Sessions/实例快照为 LumilioCL 自有流程，入口 Instance.History。

Changes 记录真实已提交的内容/配置变更；Sessions 记录明确的运行和退出事实；二者不是当前游戏文件的替代来源。读取 history.jsonl 要容错并报告跳过项，不把损坏尾行转换成新的成功记录。

快照主线：选择 full 或单世界范围 → 检查运行/操作冲突 → 一致读取 → 临时归档 → 发布 → 列表。恢复主线：选快照 → 展示将替换的单元 → 停止冲突写入 → 校验并完整 staging → 替换单元 → 重扫/记录。未在快照里的世界和设置保留；恢复替换而非目录合并。

当前 snapshots.Full 只含世界、config、options.txt、servers.dat；不含完整 mods/游戏依赖。当前（计划 0020）：staging 在操作目录里完成，提交逐单元先把原件移入 old/ 再就位，失败或崩溃按磁盘状态回滚到恢复前，启动时恢复；仍不是整次原子提交（中间态由实例租约保护）。

删除快照是用户显式操作，不使用普通 cache 自动清理策略。当前 [snapshots](../behavior/snapshots.md) 和 [history](../behavior/history.md) 是已有领域基线；service 租约与回滚已有 core 证据，真实 UI 的端到端仍需验证。验收：AC-SNAPSHOT-01、AC-SNAPSHOT-02、AC-RACE-02。

## L-DIAG-01 — 问题、日志和文件诊断

参考：H-INSTANCE-10/11、H-PLAY-06/09/10、H-SET-15。入口 Home.Needs Attention 或 Instance.Diagnostics 的 Problems/Logs/Files。

主线：聚合诊断事实 → 展示严重程度与对象 → 查看日志或文件 → 显式选择修复/改设置/管理内容 → 相关领域操作 → 重新诊断。问题摘要必须能定位目标实例和失败阶段，不只弹一次 toast。

日志缺失、无法读取、崩溃线索未知是不同结果。日志分析提供线索，不把关键词匹配当确定根因。Files 仅在实例边界浏览，不隐式提供通用编辑器或跟随 symlink 越界；导出诊断资料不得包含 token 和完整认证参数。

清理日志是明确的删除操作，和清空屏幕日志不同。当前诊断及限制见 [diagnostics](../behavior/diagnostics.md)，Home 只按 [attention](../behavior/attention.md) 生成投影。修复结果需再次核对；不以活动 succeeded 永久清除后续问题。验收：AC-DIAG-01、AC-SECRET-01、AC-FILES-01。
