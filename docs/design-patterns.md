# 共享交互模式

这些模式是设计起点，按用户任务选择和调整。功能的复杂度、使用频率和
上下文可以决定不同的布局与交互，不必为了符合模式增加控件或改写文档。
模式名供代码和讨论引用，不代表每个页面已经实现了全部建议。

当前能力见[用户路径](ia/paths/README.md)和代码；外观参考
[design-language.md](design-language.md)，措辞参考
[plain-language.md](plain-language.md)。具体 API 以项目组件和锁定依赖为准。

## P-VERSION — 游戏版本选择器

让人容易找到所需版本，并看出正式版与测试版本的区别。新建游戏通常从
最新正式版开始；编辑和筛选应保留当前意图。长列表适合搜索，非正式版
可以通过筛选或分组呈现。读取失败与“没有匹配版本”需要区分。

## P-LOADER-VERSION — 加载器版本选择

先确定游戏版本，再选择兼容的加载器版本。有可靠推荐时可突出推荐项，
同时让人查看实际版本并自行选择。游戏版本变化后重新检查兼容性；不要
悄悄把一个明确选择换成另一版本。选择器的形式取决于来源提供的信息。

## P-CONTENT-ITEM — 内容条目

条目先帮助识别对象，再提供比较所需的信息和常用操作。项目名、版本、
来源和文件名按任务取舍；没有来源信息的本地文件仍应可管理。行、卡片或
表格都可以，重复条目保持可扫描的结构。只呈现实际可用的来源与操作。

## P-VERSION-SWITCH — 切换或更新版本

让人分清当前版本、目标版本和兼容性；更新日志可以辅助决定。简单更新
不必采用双栏弹窗，复杂比较可以给详情更多空间。执行失败时保留选择并
提供恢复办法；提示快照或备份时应有可用路径，不能暗示不存在的保护。

## P-BULK — 批量操作

让选择范围和受影响数量可见，明确全选针对当前结果还是全部内容。
只提供适用于所选对象的操作；混合状态需要解释。部分失败应区分成功与
失败项，并支持处理剩余问题。工具栏的位置和是否替换原栏按空间决定。

## P-ADD-FILES — 添加本地文件

文件选择器是容易发现的入口，拖放可以作为快捷方式。显示接收目标；
遇到不支持的文件、重名或部分失败时说明处理结果。不能静默覆盖用户数据。

## P-SETTINGS-GROUP — 设置组

把一起理解或一起保存的字段放在一起，清楚区分继承值和单独覆盖的值。
即时生效、显式保存、弹窗编辑都可以；选择符合这组设置的方式，并让
结果与撤销或取消的含义明确。帮助放在需要它的地方，不强制藏进提示框。

## P-CONFIRM — 确认

确认适合代价大且难以撤销的操作；可恢复的操作可以优先提供撤销。
说明对象、范围与后果，按钮写实际动作。不要为了形式给每次操作加弹窗。

## P-STATES — 加载、空与出错

区分“尚未读取”“没有内容”“筛选无结果”和“读取失败”。尽量保留已有
上下文，提供有用的下一步。局部问题可以局部呈现，不必替换整个内容区；
已能即时显示的内容不需要模拟加载。

## P-ICON — 图标与占位

优先用对象本身的封面、项目图标或头像帮助识别；缺失时使用稳定的占位。
占位和加载失败不应妨碍读出对象名称或继续操作。装饰不承担唯一的信息。
