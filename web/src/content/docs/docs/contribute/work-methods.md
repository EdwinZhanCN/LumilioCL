---
title: 选择工作方式
description: 独立工作、Coding Agent 工作和协作工作都有明确流程。
---

三种工作方式使用相同的验收条件。
所有项目执行者都称为 `Project Maintainer`。

## 不使用 Coding Agent

1. 阅读 `AGENTS.md` 和相关 JSON 计划。
2. 检查当前行为。
3. 明确修改目标和验收条件。
4. 实现修改。
5. 运行适用的检查。
6. 评审结果。
7. 准备交接报告。

完整流程见[修改与评审](/docs/contribute/change-and-review/)。

## 作为 Coding Agent 工作

1. 修改文件前，阅读 `AGENTS.md`。
2. 阅读相关 `in_progress` JSON 计划。
3. 检查 Git 状态。
4. 阅读任务适用的 skill。
5. 检查代码和锁定版本的依赖。
6. 完成已授权的工作。
7. 运行适用的检查。
8. 把结果写回计划。
9. 报告修改和剩余限制。

除非任务授权移除，否则保留已有修改。
不要用假设代替证据。
命令失败时，报告失败及原因。
缺失信息影响正确工作时，应请求补充。

仓库访问权限不等于发布授权。
提交、推送、部署和外部消息都遵循任务指示。

## 与 Coding Agent 协作

开始前：

1. 说明预期结果。
2. 说明验收条件。
3. 明确可修改的文件范围。
4. 明确必要的手动检查。
5. 说明已授权的外部操作。

工作中：

1. 评审 Coding Agent 的发现。
2. 修正缺失或错误的要求。
3. 需要计划时，把决策写入 JSON。

交接前：

1. 阅读 diff。
2. 核对命令结果。
3. 在应用或浏览器中检查 UI 修改。
4. 记录尚未完成的手动检查。

自动检查通过不证明视觉质量。
必要验收尚未完成时，不得把计划标为 completed。
