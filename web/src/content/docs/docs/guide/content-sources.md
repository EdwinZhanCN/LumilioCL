发现页从内容来源查找和安装模组、资源包、光影和整合包。
启动器自带两个内容来源：Modrinth 和 CurseForge。
它们都是插件，在 **设置 › 插件** 里选中后，用 **启用插件** 开关单独打开或关闭。

## 切换来源

两个来源都打开时，发现页筛选栏顶部有 **Modrinth** 和 **CurseForge** 两个分段键。
窗口较窄时，筛选栏收进 **排序方式** 左边的 **筛选** 键，点它打开同样的内容。
点其中一个分段键，发现页在这个来源重新搜索：

- 搜索词、内容类型和游戏版本保留。
- 加载器、分类和排序重新开始，筛选项换成这个来源提供的。
- 下次打开发现页时仍用这个来源。

只打开一个来源时，不显示分段键。
排序只列出当前来源支持的方式，例如 CurseForge 没有按关注数排序。

## 安装 CurseForge 整合包

可以用以下任一方法：

- 在发现页切到 **CurseForge**，选 **整合包**，在结果行点 **安装**，或在详情页点 **安装为新游戏**。
- 在 **游戏库** 点 **导入整合包**，选择 CurseForge 整合包的 `.zip` 文件。也可以把文件直接拖到启动器窗口上。

安装进度显示在 **动态** 里，完成后的提示可以直接打开新游戏。
整合包作者停用的文件，安装后也是停用状态。
导入 CurseForge 整合包需要打开 CurseForge 来源。

## 只能在网站上下载的文件

CurseForge 上，有些作者只允许在 CurseForge 网站上下载自己的文件。启动器不绕过作者的设置：

- 这类项目在结果行和详情页标有 **仅限网站下载**。
- 安装时，启动器先按文件的 SHA-1 在 Modrinth 上找同一个文件，找到就从 Modrinth 下载。
- 单独安装的项目在 Modrinth 上也找不到时，启动器提示作者只允许在网站上下载它，并给出 **打开下载页**。
- 整合包里有找不到的文件时，整合包照常装好，缺少的文件列在这个游戏的 **内容** 标签里。

### 补上缺少的文件

1. 打开游戏页的 **内容** 标签。缺少的文件列在“还缺 N 个文件”下面。
2. 点每个文件的 **下载页**，在浏览器里下载它。
3. 点 **添加已下载的文件…**，选择下载好的文件，可以一次选多个。

启动器按 SHA-1 核对每个文件，把它放到该放的文件夹里，放好的文件从列表中消失。
不是这个游戏缺少的文件，启动器会逐个说明。
游戏运行时不能添加文件。

## 识别与更新

游戏页的 **内容** 标签依次用打开的来源识别已安装的文件：先问 Modrinth，没认出的再问 CurseForge。
认出的文件显示项目名、作者和版本，可以更新和切换版本；更新由识别它的那个来源检查。
某个来源连不上时，文件照常列出并注明。

发现页的 **已安装** 和 **更新** 只认得当前来源识别的文件。

## 翻译简介

在 **设置 › 通用** 打开 **翻译** 后，发现页的结果行和详情页顶部显示简体中文简介。

- 启动器先向 MCIM 镜像（mod.mcimirror.top）要译文，MCIM 没有的再向 launcher.lumilio.org 要。
- 这两处只收到来源平台的名称和项目 ID。
- 两处都没有译文时，简介保留原文。
- 详情页的正文不自动翻译。点 **翻译** 后，正文发送给 **翻译提供商**，目前只有 Microsoft Edge。点 **显示原文** 换回原文。
- 译文在本机保存 7 天。要提前删除，在 **设置 › 通用 › 翻译缓存** 点 **清除**。
- 目前只翻译成简体中文，标题不翻译。

## 限制

- CurseForge 来源需要 API 密钥。从 GitHub 下载的正式版已经内置密钥；自己编译时没有设置 `CF_API_KEY`，CurseForge 来源默认关闭，插件说明里写明了原因。
- 启动器发往 CurseForge API 的请求不经过下载镜像。
- 游戏库的 **导入其他启动器的游戏…** 不支持 CurseForge 桌面应用的实例文件夹。请在 CurseForge 应用里导出整合包，再用 **导入整合包** 导入。
- 发现页一次只显示一个来源的结果，不合并两个来源的搜索。
