# 0030 — 游戏页·运行时：更换游戏版本与加载器、修复游戏文件

- Status: in_progress
- Phase: Phase 8 — ARCH 页面接入和视觉验收
- Author: agent

## Goal

游戏页·设置·运行时：更换游戏版本、更换加载器与加载器版本（L-LIB-07），以及修复游戏文件（H-INSTANCE-11）。更换前提示可能不兼容并可一键「先建快照」；提交前保留旧的可用组合，失败或取消不会留下半截状态；完成后重新校验并写入历史。

## Scope

- In scope：core `change_runtime`（先准备新组合的共享文件，再在实例租约下提交记录变更，失败回滚到旧组合；不改写其他实例共用的 release）；修复（核对并补齐/重下损坏文件，复用 `InstallationVerifier`/`RepairExecutor`）；UI 运行时分段（版本与加载器行、P-VERSION / P-LOADER-VERSION 弹窗、警告与「先建快照」、修复按钮）；活动页可见与历史记录。
- Out of scope：整合包更新（识别包管理文件）、跨加载器迁移 Mod 的兼容性判断。

## Tasks

- [x] T1: core `change_runtime` 的契约与测试（成功、下载失败、取消、提交失败回滚）。
- [x] T2: core 修复入口与测试（损坏文件被补齐，natives 重建，已完好则无动作）。
- [x] T3: UI 运行时分段、版本/加载器弹窗、警告与先建快照。
- [x] T4: app 接线、活动与历史、四项检查、实机验证。
- [ ] T5: 视觉验收（运行时分段、更换弹窗、先建快照、修复）：待维护者检查。

## Validation

四项检查；在假服务器上换版本失败时旧版本仍可启动；修复前后文件哈希一致；历史里有一条变更记录。

## Outcome

- core：`change_runtime`（先准备新组合再提交，失败/取消/提交失败都回到旧组合且可离线启动）、`repair_instance`（复用启动时的校验，完好时无网络无动作）、`InstanceStore::set_runtime`（单个库事务，失败回滚测试已覆盖）。
- UI：`NewGameForm` 增加更换模式（起点是游戏现在的组合，相同组合不能提交，警告与「先建快照」），运行时分段的「更换…」「修复」。
- 没有在真实网络下点过更换（测试用本地服务器覆盖了成功、下载失败、取消、提交失败）；请你在验收时实际换一次版本。

## Risks / open questions

- 换版本前建议快照，但不强制；若快照失败要阻止还是允许继续，实现前和维护者确认。
