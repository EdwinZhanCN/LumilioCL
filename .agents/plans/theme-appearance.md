# 主题与外观

- Status: proposed

## Goal

除了现在的浅色铝和深色夜，人可以换一套主题、调整界面字体和字体大小。主题改变的是语义颜色、圆角、密度和字体，不替换控件本身。内置的两套外观保持设计语言里的样子。自定义主题是启动器数据目录里的 JSON，改完即可在选择器里看到。

## Scope

- In：主题文件、浅色/深色成对、跟随系统、字体族、字体缩放、对比度校验、本地主题目录。
- Out：代码高亮主题、每个控件一套自由样式、社区主题商店、用主题关掉焦点环或减弱动效、像素字体作为界面正文。

## 调研

Zed 的主题是 JSON。一个文件可以包含多套 `themes`，每套有 `name`、`appearance`（`light` 或 `dark`）和 `style` 颜色。设置里的 `theme` 可以是一个名字，也可以是 `{ mode, dark, light }`，`mode` 能为 `system`。`theme_overrides` 只改某一套的若干键。字体不在主题色板里，而在设置里：`buffer_font_family`、`buffer_font_size`，终端可以另选字体（<https://zed.dev/docs/themes>，<https://zed.dev/docs/reference/all-settings>）。本地主题放在用户的 `themes` 目录，下次启动出现在选择器中。Zed 还有两百多个编辑器色标；那些语法色和协作者颜色与启动器无关。

本仓库的颜色已经是语义层：`crates/lumilio-ui/src/theme.rs` 里每种外观有中性底、三种按键色和一种信号橙。字体是 Space Grotesk、JetBrains Mono、系统中文和只用于显示屏的 DSEG7（设计语言 §13）。主题系统应该覆盖这一层，而不是让 JSON 指定某个按钮的 GPUI 样式。

「组件样式」在这里指圆角、间距密度和按键/面板/字段的色板。控件仍来自 `lumilio-ui` 的 `kit`。主题不能把焦点环对比度降到不可见，也不能把中文界面改成像素字体。字体大小是一套缩放，作用在正文、标题和数值上，显示屏的 DSEG7 不跟着放大到破版。缩放有上下限。

跟随系统只切换已经选好的浅色主题和深色主题。自定义主题与内置主题使用同一个结构。缺字段时用当前外观的内置值补齐，并在选择器里说明缺了什么。对比度不够的文件拒绝启用，保留上一套有效主题。

社区分发主题留给目录计划。这一轮只读本地目录。

## Tasks

- [ ] T1：定一份主题 JSON。字段覆盖现有语义色、圆角、密度、无衬线字体、等宽字体、可选的中文覆盖字体、字体缩放。内置铝与夜用同一结构序列化，保证内置主题也能通过校验。
- [ ] T2：设置里选择主题、浅色/深色/跟随系统、字体和缩放。本地主题目录出现在列表中。非法文件显示原因，不替换正在用的主题。
- [ ] T3：把散落的颜色和字号改为读取当前主题。英雄区的像素画不跟着主题换色。DSEG7 仍只出现在显示屏上。
- [ ] T4：对比度测试。正文对底色、焦点环对底色低于阈值时校验失败。缩放上下限有测试。

## Validation

- 内置浅色和深色的截图式测试或颜色快照与主题文件一致。
- 一份缺字段的主题能启用，缺的键等于内置值。
- 一份对比度不足的主题被拒绝，界面留在上一套。
- 切换字体和缩放后，设置、发现和实例页同时变，游戏日志的等宽字体跟着等宽族，中文仍能回退到系统字体。
- 实机：浅色、深色、720 宽窗口各看一次自定义主题，焦点环仍清楚。

## Open questions

- 中文覆盖字体只在该字体确实安装时启用。找不到文件里的字体名时回退系统中文，并在外观页说明，不静默使用拉丁字体去画汉字。
