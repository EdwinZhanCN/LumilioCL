# 0037 — 下载源策略与解析回退

- Status: accepted
- Date: 2026-10-07

## Context

ADR 0033 的镜像预设仍沿用二选一开关：关闭镜像优先也会在官方失败后使用镜像，MCIM 又会随全局偏好提前。元数据读取只检查 HTTP 和大小，收到坏 JSON 后不会尝试下一源。维护者同意参考 HMCL 对齐这些行为。

参考 HMCL 的 `DownloadProviders.java`、`BMCLAPIDownloadProvider.java` 和 `MultipleSourceVersionList.java`，保留 Rust 的 SourceChain 与 crate 边界。

## Decision

提供“仅官方 / 官方优先 / 镜像优先”，默认官方优先。旧 `prefer_mirrors` 的 false / true 分别解释为官方优先 / 镜像优先；新偏好显式保存，兼容字段继续写入。仅官方保留已配置规则，但不把它们放入请求候选。

识别内置 MCIM 规则对，将其固定排在官方之后；其他自定义规则保留既有相对顺序。规则编辑、清空与添加预设只改变规则，偏好独立保存，避免异步操作用旧快照覆盖另一个设置。

元数据候选在解析和对应结构检查通过后才被接受。游戏目录、Fabric / Quilt 列表及配置、Forge / NeoForge 列表、启动清单、Java 目录与清单、authlib-injector 最新信息采用这一边界；所有源失败时保留各源原因。合法空列表仍有效，本地已安装清单的读取路径保持现有行为。

## Consequences

选择仅官方的人得到明确的源限制；MCIM 作为后备，减少对镜像更新时效的依赖。坏 JSON、错误结构和无效编码不会阻断后续可用源。远端解析错误通过候选失败聚合报告，Java 元数据失败归入安装失败。

版本列表与文件下载暂时共享偏好，后续如有使用需求再拆开；本次不增加地域判断、测速或系统 HTTP / SOCKS 代理。
