# 0008 — 用户流程覆盖与待决策边界

- Status: rejected
- Date: 2026-09-30

## Context

本地 HMCL 流程盘点与 App State 目标需要服务于后续开发，但 HMCL 功能范围比 ARCH 更大，已有 core 服务也不等于完整 UI 业务路径。需要显式记录缺口，避免文档盘点悄悄扩大产品范围。

## Decision proposal

建议以 [用户流程入口](../../docs/workflows/README.md) 连接参考行为、目标流程、现有 behavior 和验收场景，保留 H/L/AC 稳定编号。不改变 ARCH、ADR 0006，或把 proposed ADR 0007 宣称为已实现。

以下问题在实施相应功能前决定，本 ADR 尚不选择答案：

| 问题 | 现有约束 | 决策触发点 |
|---|---|---|
| 全局账户、全局默认和应用维护入口 | ARCH 只有五个主要节点；实例 Settings 不能冒充全部全局功能 | 接入全局设置/账户 UI 前明确入口与导航归属 |
| 在线身份和第三方认证 | 目前 core 只实现离线账户；秘密按 App State 放系统库 | 客户端注册、账户协议、会话登录与离线资格设计 |
| 资源包「启用」的语义 | 当前 content 是文件可用性切换；HMCL 使用资源包管理器操作选择状态 | 若宣称在启动器内控制游戏资源包选择，先定义 options.txt 与文件状态的关系 |
| 游戏运行时允许哪些文件操作 | HMCL 的世界锁可参考；LumilioCL 尚缺统一跨操作锁和会话规则 | 删除、复制、更新、快照恢复接入完整服务前 |
| 目录、外部工具、主题包、联机 | 有 HMCL 入口；外部数据根不在 App State 首轮，其他能力无 ARCH 节点 | 需求明确纳入时独立范围 ADR |
| 导出包、个人备份、完整离线备份 | 目的和内容不同，秘密/缓存不应导出 | 实施备份恢复或多格式整合包导出前 |

## Consequences

- Positive: 后续计划可定位到可核对的行为与验收，规划不会伪装成实现。
- Negative / trade-offs: 流程目录需随参考版本和已实现行为维护；静态审计不替代运行验证。
- Follow-ups: 相关计划引用具体问题与 L/AC 编号，决定后更新或用独立 accepted ADR 取代；首轮只交付文档。

## Rejected

2026-10-03：用户流程文档（`docs/workflows/`）连同 H-/L-/AC- 编号一起删除，见 ADR 0021。
