# 0038 — 界面语言：Fluent 目录、编译期检查与插件自带文字

- Status: accepted
- Date: 2026-10-08

## Context

启动器的文字原先直接写在 Rust 里，只有简体中文。要提供英文，并且在设置里即时切换，不必重启。gpui-component 自带 `rust-i18n`，但它不支持复数（longbridge/rust-i18n#65），英文的「1 rule / 3 rules」需要按 CLDR 规则选形式。core 不依赖 UI（不变量 1），也就不能自己格式化给人看的句子。

## Decision

1. **目录。** 启动器的文字放在 Project Fluent 目录 `crates/lumilio-ui/i18n/<语言>/lumilio-ui.ftl`，由 `i18n-embed` 嵌入二进制。简体中文是回退语言，必须完整；英文按同一组 id 与参数补齐。gpui-component 内部仍用自己的 `rust-i18n`，切换语言时一起设置。
2. **取词。** `tr!("id")` 经 `i18n-embed-fl` 在编译期按中文目录检查 id 与参数。无参数的消息按（语言，id）格式化一次并保留，返回 `&'static str`，可以直接替换原来的字面量；带参数的返回 `String`。`tr_all![…]` 给选项和分段一组标签。只在运行时才知道的 id（Modrinth 标签）走 `i18n::lookup`，查不到时显示原名。一句话是一条消息，不在代码里拼片段；计数作为参数，由目录选复数形式。
3. **切换。** 偏好 `Preferences.language`：跟随系统、简体中文、English。跟随系统时取系统语言列表里第一个中文或英文，都没有则用简体中文。切换时换目录、设置 gpui-component 并刷新窗口；`i18n::generation()` 随每次切换递增，把文字存进实体状态的控件（输入框占位符、下拉选项）据此重新取词，并保留已选的项和已输入的文字。数字分组这类按语言不同的格式在代码里按 `i18n::locale()` 分支（万 / K）。
4. **core 返回类型。** core 的结果和错误不带人话：动态任务标题是「操作 + 对象」，旧日志里的文本标题原样显示；回收原因、直达目标的问题、早期版本分组、导入来源都是枚举，由 UI 映射。core 错误的 `Display` 是英文技术描述，放在技术详情里。会写进用户数据的名字不由 core 选语言：恢复备份时重名改为加「 (2)」这类编号。
5. **插件自带文字。** 宿主不翻译插件。清单的名称、描述、设置标签与说明、页签标题是 `Words`（中文与英文各一份，界面渲染时挑选）；插件运行中生成的文字按 `HostContext::locale()` 给出。设置的选项字符串是保存的值，不翻译。社区插件以后可以照此自带语言。
6. **护栏。** 测试要求英文目录覆盖中文目录的全部 id 且参数一致，并且两个目录都能解析。UI 与 app 源码里的中文字面量只能出现在 `hardcoded.txt` 列出的范围内，这份清单只许变短，现在为空；故意保留的中文行在行尾写 `// i18n-exempt: <原因>`。语言切换的测试在单独的测试进程 `tests/english.rs` 里，避免与断言中文的单元测试相互干扰。

## Consequences

- 加一种语言只需要加一个目录，代码不动；复数、占位符都在目录里表达。
- id 写错或参数对不上会编译失败；英文缺条目、写错 Fluent 语法会让测试失败。
- 无参数消息常驻内存，总量受目录大小限制（约 1200 条乘以语言数）。
- 运行时查找的 id（Modrinth 标签）没有编译期检查，靠回退显示原名。
- 旧动态日志里的中文标题不会被翻译。
- 英文由 DeepSeek（维护者的 `dsh`）按 skill `lumilio-i18n` 的提示词起草，人审后提交；dsh 不在 CI 中。

## Shipped

Fluent 目录（约 1200 条中英消息）与 `tr!` / `tr_all!` / `lookup`；设置·通用的语言选项与即时切换；全部页面、对话框、提示与 app 的提示文字进入目录；core 结果与错误改为类型；插件清单与插件生成的文字按语言给出；平台相关的「在访达中显示 / 在文件资源管理器中显示 / 在文件管理器中显示」；设计语言 §8 的英文语气规则。维护者在英文界面下看过布局，观感可以。
